上線計畫 · v1.0

AIPager 上線計畫：從單機測試到多台實機日常使用

P0 已實作並在單機 Linux 通過自動化測試，也用真實 Claude Code 驗證過關鍵行為。接下來要在你的真實機器上一台一台接上：先 Ubuntu Hub，再 Windows build-pc，再開發機、Mac 筆電、Linux。這份文件寫明每一步怎麼跑、怎麼驗收、怎麼回報、出問題怎麼退回。

日期 2026-11-03 對應實作 v0.5（PR #2） 設計規格 aipager-design.html 測試清單 spec/tests/test-plan.json

01目的與現況

這份文件的用途

  • 把「接下來怎麼把 AIPager 跑在真實機器上」寫成可以照著做的步驟，任何人接手都看得懂、不會做歪
  • 每個階段列出要跑的測試項目；測試項目與目前狀態直接取自 spec/tests/test-plan.json，那份檔案更新後本文件重新建置就會反映
  • 寫清楚哪些事只能由你在實機上做、哪些事由 Claude 做，以及結果怎麼回報

現況

測試進度：手動測試 34 項：未執行 11、部分完成 20、通過 3、失敗 0。自動化測試 12 項，最近一次通過 12 項。

Hub、Worker、MCP、aipagerctl、aipager-hint、Dashboard已實作自動化測試 A01–A12 全部通過（Ubuntu 24.04 容器、單機）

Ubuntu 26.04部分24.04 已實跑；26.04 的 Rust coreutils 與 sudo-rs 未驗證

三條原則

  1. 一次只接一台機器。每台機器的驗收項目全部通過（或已記錄原因）才接下一台，出問題時範圍小、好排查
  2. 所有結果都要記錄。每跑完一個測試項目，結果寫回 spec/tests/test-plan.json（日期、環境、結果、說明），文件與測試清單永遠一致
  3. 先實測再下結論。Windows 與 macOS 的程式路徑都還沒在真機跑過，任何「應該可以」都要以實際輸出確認；發現問題先修程式並補自動化測試，再繼續

兩種進行方式

A. 你操作，貼回結果 預設

  • 照本文件每一步的指令在該機器執行
  • 把指令與完整輸出貼回對話；失敗時另附診斷檔（12 回報方式與記錄）
  • Claude 判讀、修正、記錄，再給下一步

B. 把機器接上 Claude 的 session 較快

  • 在該機器開啟 Claude Desktop 的 Remote Control（設定 → Claude Code → Remote Control），或在專案資料夾執行 claude remote-control
  • 之後 Claude 可以在你核准下直接在那台機器執行指令、讀 Log，省去來回貼輸出
  • 闔蓋、重開機、輸入 Windows 密碼等仍需要你本人操作

分支與 PR 規則

  • 每個上線階段的修正開一個新分支（例如 claude/rollout-r2-windows），一個階段一個 PR，PR 說明附上該階段的測試結果
  • 不直接改 main；不使用 git worktree
  • 每個 PR 合併前 npm test 必須全部通過；改到 Worker 執行 claude 的部分時，另跑 npm run test:real-claude

05R1 Ubuntu Hub

目標：一台常駐開機的 Ubuntu 24.04（或 26.04）跑 Hub，其他機器透過 Tailscale 用 http://aipager-hub:7300 連到它。詳細設計見規格的 部署 章節。

1. Tailscale 與機器名稱

Hub 機
sudo apt-get update && sudo apt-get install -y git curl xz-utils
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
tailscale ip -4

在 Tailscale 管理頁把這台機器改名為 aipager-hub，其他機器才能用這個名稱連線。若不改名，之後所有指令中的 aipager-hub 都換成實際的 MagicDNS 名稱或 100.x 位址。

Hub 機（x64；ARM 主機把 linux-x64 換成 linux-arm64）

sudo mkdir -p /opt/node-v22
sudo tar -xJf node-v22.23.4-linux-x64.tar.xz -C /opt/node-v22 --strip-components=1
/opt/node-v22/bin/node -e "require('node:sqlite'); console.log('sqlite ok')"

預期：最後一行印出 sqlite ok（前面可能有一行 ExperimentalWarning，屬正常）。

Hub 機

  • webhooks：改成 []。依 Q7 決定不推播，只用 Hub 查詢；範本裡的 ntfy 位址只是範例，留著只會產生連線失敗的 Log

06R2 Windows build-pc

目標：Windows build-pc 以「登入 Claude Code 的那個 Windows 帳號」常駐 Worker，重開機不登入也能接任務。這是 Windows 程式路徑第一次在真機上執行，預期可能遇到問題，每一步都要看輸出。

0. 先讓你的電腦以互動機加入

aipagerctl send 必須從一台已加入的機器發出。先在你的電腦（R1 步驟 4 那台）建立加入碼並以 --no-worker 加入：

你的電腦（repo 目錄）

node bin/aipagerctl.js join --hub http://aipager-hub:7300 --code ape_上一行的加入碼 --no-worker --node-id dev-pc
node bin/aipagerctl.js doctor

機器類型依實際情況填 laptop 或 desktop。doctor 會因為沒有 Worker 而略過 claude 檢查，其他項目應為 OK。

1. build-pc 前置安裝

build-pc：一般 PowerShell，以要跑 Worker 的帳號
winget install --id Tailscale.Tailscale -e
winget install --id Git.Git -e
winget install --id Volta.Volta -e

volta install node@22

claude --version

  • 執行一次 claude，用 Max 帳號登入後 /exit（Q5）
  • Git for Windows 是 Claude 的 Bash 工具所需，不能省略
  • node -e 若回傳 -1073741819，是 Node 原生崩潰，先處理 Node 安裝本身
  • 依 N4 關閉 Claude Code 自動更新，做法見 11 R7 日常運作與升級 的「Claude Code 升級」；步驟 3 建立 profile 時記得加上 env

3. 測試用 profile

join 只建立了唯讀的 echo profile。T11、T13 需要能跑長時間指令的 profile，編輯 C:\ProgramData\AIPager\node\profiles.json，在 profiles 裡加入：

profiles.json 內新增（JSON 中反斜線要寫兩個）
"longrun": {
  "description": "測試用：長時間指令（T11 取消、T13 逾時）",
  "workdir": "C:\\ProgramData\\AIPager\\worker\\sandbox",
  "model": "haiku",
  "permission_mode": "default",
  "allowed_tools": ["Bash(ping:*)", "Bash(sleep:*)"],
  "approval": { "auto_deny": ["*"] },
  "max_turns": 5,
  "timeout_sec": 900

存檔後不用重啟：Worker 會自動重新載入，Dashboard 的節點頁會出現 longrun；如果格式錯誤，節點頁會顯示紅色的 profiles.json 錯誤並沿用舊設定。

07R3 開發機互動與第一個實際流程

目標：在你的 Claude Code 對話中直接說「叫 build-pc 編譯」，完成 Q8 的實際流程。依 Q4，build-pc 以 SSH 唯讀 deploy key 存取 Git server；開始前請提供 Git server 的種類與 repo 網址。

1. 註冊 MCP 與未讀提示

你的電腦：Windows
claude mcp add --scope user --env AIPAGER_AGENT=main aipager -- node "C:\你的repo路徑\bin\aipager-mcp.js" --mode interactive
你的電腦：macOS / Linux
