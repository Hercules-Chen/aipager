主迴圈

  1. 啟動自檢：偵測 os / arch；讀 node.json、token、profiles.json；確認 claude --version 可執行、資料目錄可寫入；補送「有 result.json 但未送出」的任務；把「沒有 result.json 也沒有程序」的任務以 E_WORKER_CRASH 回報
  2. 心跳：每 15 秒 POST /nodes/heartbeat（帶 facts、profiles、目前持有的 meta_version）；回應中的 cancel_requests 立即處理，有新 metadata 就更新本機快取
  3. 領任務：有空位時 POST /tasks/claim?wait=25（long-poll），帶上目前沒被鎖住的 profile
  4. 建任務目錄：<資料位置>/tasks/yyyyMMdd/<task_id>/，寫入 task.json、task.token、profile.json（任務結束即刪除 token）
  5. 準備工作目錄：若有 repo：檢查 url 在 allow_remote 內 → git status --porcelain 必須乾淨 → 執行 pre_commands → git checkout --detach <commit>。附件下載到 .aipager/inputs/<task_id>/
  6. 組 prompt：依範本產生 prompt.txt 與 system-append.txt（含 os、arch、shell 提示），產生 mcp.json（task 模式）
  7. 啟動 Claude：以參數陣列 spawn（不經 shell），prompt 從 stdin 寫入；POSIX 上以 detached:true 建立獨立程序群組；macOS 若 keep_awake 則同時啟動 caffeinate -i -w <pid>
  8. 執行中：stdout 逐行寫入 stream.jsonl 並解析；每 20 秒續約；轉送進度（節流 2 秒）；收到取消或逾時就依平台終止程序樹（見 ）
  9. 收尾：決定結果來源（見下）→ 驗證 json 輸出 → 收集 artifacts（相對路徑、禁止 ..、總量上限）→ 上傳 blob → 上傳壓縮後的 stream.jsonl（供 Dashboard 檢視）→ POST /result
  10. 送不出去：Hub 連不上時把結果留在 result.json 並標記 pending，背景以指數退避重送（最長間隔 5 分鐘）

心跳、睡眠偵測與熱重載

  • facts：啟動時與每小時重新偵測一次（OS 版本、Claude 版本、Tailscale IP 等），變動時隨心跳送出
  • 睡眠偵測：每 5 秒比對牆上時間，跳動超過 30 秒即判定剛醒來，立刻送心跳並帶 resumed_from_sleep_sec，同時把這段時間記為該任務的睡眠區間（逾時只算醒著的時間）
  • retired：心跳收到 401 時停止領任務、在 Log 寫明「此節點已退役或 token 已撤銷」，每 10 分鐘重試一次，不再狂打 Hub
  • profiles 熱重載：監看 profiles.json，存檔後驗證通過才替換；失敗保留舊設定並在心跳回報 profiles_error

Claude 啟動參數（三個平台相同，只有路徑不同）

Worker 組出的參數（cmdline.txt 會記錄，不含 token）
<claude_path> -p
  --output-format stream-json --verbose
  --model sonnet
  --max-turns 30
  --permission-mode acceptEdits
  --allowedTools "Read" "Grep" "Glob" "Bash(git status:*)" "Bash(dotnet build:*)" …
  --disallowedTools "Bash(git push:*)" "WebFetch" …
  --mcp-config "<任務目錄>/mcp.json"
  --strict-mcp-config
  --permission-prompt-tool mcp__aipager__permission_prompt
  --append-system-prompt "<system-append.txt 的內容>"
  [--resume <claude_session_id>]        ← 只在 session.mode=resume_thread 且 Hub 有紀錄時

cwd   = profile.workdir
stdin = prompt.txt（UTF-8）
env   = 使用者環境 + profile.env + AIPAGER_TASK_ID + MCP_TOOL_TIMEOUT=900000
        + 依 claude_auth 注入 CLAUDE_CODE_OAUTH_TOKEN 或 ANTHROPIC_API_KEY（並移除另一個）
  • claude_path：Windows 指向 claude.exe（原生安裝版；Node 在 Windows 上 spawn .cmd 需要 shell:true，會引入參數跳脫問題，v1 不支援）；macOS / Linux 為 ~/.local/bin/claude
  • --strict-mcp-config 讓任務 session 只載入 aipager，不受操作者個人 MCP 設定影響
  • --resume 只能在同一台、同一個 cwd 找到舊 session，因此 resume 記錄以 (thread, node, profile) 為鍵
  • launchd 與 systemd 啟動時 PATH 很短，服務設定檔必須明確給 PATH（範本已設定 Volta 與 ~/.local/bin）

結果判定優先序

  1. Claude 有呼叫 submit_result → 採用它（result_source=submit_tool）
  2. 沒呼叫，但串流最後的 result 事件 subtype 為 success → 狀態 succeeded，summary 取最後文字前 4000 字（final_text）
  3. 其他情況 → failed，依 error_max_turns、exit code、逾時、取消、驗證錯誤對應錯誤碼（worker）

stream-json 對應

Claude 事件Worker 動作
type=system, subtype=init取得 session_id、載入的工具與 MCP 狀態；若 aipager MCP 未連上則記 warn → progress started
type=assistant 含 tool_useprogress phase=tool（工具名 + 參數摘要 ≤ 300 字）

無法解析的行原樣保留在 stream.jsonl，Log 記 warn，不中斷任務

程序終止（已實測）

POSIX 的做法已在 Linux 上實測：以 detached:true 啟動含多層子程序的 bash，對整個程序群組送 SIGTERM 後，群組內沒有任何仍在執行的程序。測試環境中剩下的兩個項目是殭屍狀態（Z），原因是容器的 PID 1 不回收子程序；真機上的 systemd 與 launchd 會回收。因此 Worker 檢查孤兒程序時要排除 Z 狀態，否則會誤判。

Profile 設定

Profile 是接收端的安全邊界：發送端只能選 profile 名稱，工作目錄、可用工具、模型、上限都在這裡決定。每台機器的 profiles.json 用自己平台的路徑與指令。

Windows：profiles.windows.json（echo 冒煙測試 + build 編譯）
spec/config/profiles.windows.json
macOS：profiles.macos.json（echo + ios 建置測試）
spec/config/profiles.macos.json
Linux：profiles.linux.json（echo + e2e 測試）
spec/config/profiles.linux.json
工作目錄策略：每個 profile 使用 Worker 專屬的 clone（例如 D:\AIPagerWork\erp、~/AIPagerWork/ios-app），不與開發者自己的工作副本共用，也不使用 git worktree。工作目錄不乾淨時直接以 E_WORKDIR_DIRTY 失敗，不自動清除，避免誤刪。
