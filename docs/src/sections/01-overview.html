要解決的問題

現況是每台機器各自跑 Claude Code，要協作時只能由人複製 A 機的輸出、貼到 B 機。AIPager 提供一個中控站（Hub），讓各機器的 Claude 用固定的協定互相傳遞「任務」與「訊息」，不論那台機器是 Windows、macOS 還是 Linux，也不論它是常駐的伺服器還是會闔蓋睡覺的筆電。

範圍內（v1）

  • 派工：A 機的 Claude 指派任務給 B 機，B 機自動執行並回報結果
  • 動態加入：新機器用一次性加入碼自行登錄，不需要預先列清單
  • 機器資料可調整：名稱、角色、標籤、機器類型存在 Hub，隨時修改、有版本紀錄
  • 在線判斷：以心跳判斷在線 / 睡眠 / 離線；派給睡著的機器時提醒發派者與使用者
  • 跨平台：Hub 在 Linux；Worker 與互動 session 可在 Windows、macOS、Linux
  • 條件路由：任務可要求作業系統、CPU 架構、標籤（例如 xcode=16）
  • 訊息、流水線、人工審核、全程追蹤

範圍外（v1 不做）

  • 對網際網路公開的 Hub；v1 只在 Tailscale 內使用
  • 多使用者、多帳號權限；v1 假設所有機器屬於同一個人或小組
  • 取代 Git 同步程式碼；程式碼一律走既有 Git server
  • Hub 的高可用（多台 Hub）；v1 單一 Hub，搭配每日備份
  • 遠端喚醒睡著的機器（Wake-on-LAN）；v1 只提醒、排隊等待

已確認的前提

代號內容來源
C1Hub 放在 Ubuntu 24.04 LTS 或 26.04 LTS，使用 systemd，常駐開機使用者確認
C2所有機器裝 Tailscale，透過 tailnet 互通；Hub 只綁 Tailscale IP，節點以 MagicDNS 名稱 aipager-hub 連線使用者確認
C3機器清單不固定，會陸續加入；機器資料要能隨時調整使用者確認
C4Mac 一開始是筆電，會睡眠；以心跳判斷，派工時提醒使用者確認

仍為假設（見 ）

代號假設若不成立的影響
A1每台 Worker 都已安裝 Claude Code，並以某個作業系統帳號完成登入aipagerctl join 的檢查會失敗並說明原因
A2程式碼放在既有 Git server，各 Worker 可 fetch只能傳小檔附件，不適合傳整個專案
A3Node.js 22 LTS。Worker 以 Volta 鎖版，Hub 用官方 tarball 固定路徑（本規格的驗證腳本已在 22.23 實測）升 24 LTS 時需重跑 tools/validate-spec.js

名詞

名詞意義
Hub中控服務，跑在 Linux。只負責存放、轉送、排程、記錄；不執行任何程式，也不需要安裝 Claude
Node（節點）一台加入 AIPager 的機器，以 node_id 識別（例如 build-pc、macbook-hc），node_id 加入後不可改
MetadataHub 上可隨時修改的機器資料：顯示名稱、角色、標籤、機器類型等
Presence（在線狀態）依心跳判斷：online / asleep / offline / never
Enrollment（加入碼）一次性代碼，新機器用它換得 node token
WorkerNode 上的常駐程式，向 Hub 領任務，啟動 claude -p 執行
Agent / MailboxNode 上的收件匣名稱。worker 是 Worker 本身；互動 session 預設是 main
Task（任務）要另一台機器「做事」的請求，有完整生命週期與結果
Message（訊息）純資訊傳遞，不會自動觸發任何執行
Thread一串相關的任務與訊息（例如一次「開發 → 編譯 → 測試」）
ProfileWorker 本機定義的執行設定：工作目錄、允許的工具、模型、逾時。任務只能指定 profile 名稱
Lease（租約）Worker 領到任務後的持有期限，需定期續約；過期代表 Worker 失聯
Tracetrace_id 串起同一次請求在各機器上的所有事件與 Log
