共六個元件，全部以 Node.js 撰寫，共用同一個 relay-client 函式庫（HTTP 呼叫、重試、Log 格式、設定檔讀取、各 OS 預設路徑），避免各元件、各平台各寫一套。

元件跑在哪以誰的身分職責主要相依
relay-hubUbuntu Hub 機（1 台）系統帳號 claude-relay（systemd）REST API、SSE、Dashboard、節點登錄與 metadata、在線判斷、佇列、租約、逾時、審核、附件、條件路由、備份Fastify 5、Ajv 8（draft 2020-12）、node:sqlite
relay-worker每台執行任務的機器（Windows / macOS / Linux）已登入 Claude Code 的那個使用者心跳（含 facts 與睡眠偵測）、領任務、準備工作目錄、啟動 claude -p、解析串流、續約、取消、上傳結果、profiles 熱重載relay-client、Claude Code CLI、Git
relay-mcp每台機器（由 Claude Code 自動啟動）啟動它的 Claude Code把 Relay 能力包成 MCP 工具；有 interactive 與 task 兩種模式@modelcontextprotocol/sdk（stdio）
relay-hint有互動 session 的機器Claude Code hook每次輸入 prompt 時查詢未讀摘要，有未讀才輸出一行提示relay-client
relayctl任何機器操作者加入（join）、安裝服務、查節點、改 metadata、建立加入碼、送任務、看 Log、審核、健康檢查、備份relay-client
DashboardHub 提供 /ui瀏覽器（admin token）節點清單與在線狀態、待核准機器、metadata 編輯與歷史、任務即時串流、審核佇列、Thread 與 Trace；zh-TW / en原生 ES modules（不打包，方便 Chrome DevTools 除錯）

relay-hub Ubuntu · port 7300

  • 只綁 Tailscale IP（listen.host）；開機時 Tailscale 還沒就緒的話，每 5 秒重試綁定並寫 Log
  • 背景工作：每 5 秒掃過期租約（筆電睡眠中套用保留時間）；每 15 秒重算各節點在線狀態並記錄變化；每 30 秒掃 TTL 與逾時；每日清理與備份
  • 啟動時把所有進行中任務的租約延長 120 秒，避免 Hub 重開就把任務判失敗
  • systemd 強化設定：唯讀系統、只開放 /var/lib/claude-relay 與 /var/log/claude-relay 寫入

relay-worker outbound only

  • OS、架構、版本等 facts 自動偵測並在心跳回報；角色與標籤由 Hub 管理，不寫在本機
  • 每 5 秒檢查牆上時間是否跳動，偵測到從睡眠醒來就立即送心跳
  • 監看 profiles.json，存檔後驗證並自動重新載入
  • 各平台用原生服務管理員啟動，由 relayctl service install 一鍵註冊

relay-mcp stdio

  • interactive 模式：給你手動開的 Claude Code 用，身分是 <RELAY_AGENT>@<node_id>；派工預設 on_unavailable=confirm
  • task 模式：Worker 為每個任務產生專屬 MCP 設定，帶 task token，多出 relay_submit_result、relay_report_progress、relay_permission_prompt；派工預設 queue
  • token 從本機設定目錄讀取，不寫進 Claude 的設定檔

relayctl CLI

  • join：用加入碼登錄本機，寫好 node.json、token、預設 profiles.json
  • service install | uninstall | status：依平台註冊工作排程器 / launchd / systemd --user
  • nodes show | set | history | rollback | approve | drain | disable | retire
  • enroll create | list | revoke（admin）
  • 派工時目標沒在線，直接在終端機詢問 排隊 / 改派 / 取消
