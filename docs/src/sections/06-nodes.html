機器會陸續增加、更換、搬位置，所以 Relay 不預先寫死機器清單。新機器用一次性的加入碼自行登錄；顯示名稱、角色、標籤、機器類型等 metadata 都存在 Hub，隨時在 Dashboard 或用 relayctl 調整，不需要登入那台機器、也不需要重啟 Worker。唯一不能改的是 node_id，因為它是位址的一部分。

節點資料分三層

層內容誰寫入存在哪怎麼改何時生效
facts（事實）os、arch、OS 版本、主機名稱、Tailscale IP、時區、Worker 與 Claude 版本、登入模式Worker 自動偵測，每次心跳回報Hub不能手動改下一次心跳
meta（管理資料）顯示名稱、說明、角色、標籤、機器類型、在線判斷設定、負責人、備註管理者Hub（有版本紀錄）Dashboard 或 relayctl nodes set派工路由立即生效；Worker 在 15 秒內的下一次心跳取得新版
local（本機設定）node.json（Hub 位址、token 檔、claude 路徑、登入模式、Worker 參數）、profiles.json（能做哪些事）relayctl join 產生，之後由該機管理者編輯該機器在該機器上編輯檔案profiles.json 自動重新載入；node.json 需重啟 Worker
為什麼 profiles 不放 Hub：profile 決定這台機器允許 Claude 做什麼（工作目錄、可用指令），是本機的安全邊界。放在本機代表就算 Hub 被入侵，也無法遠端放寬任何一台機器的權限。Hub 只看得到 profile 的名稱與說明。

metadata 欄位

欄位格式用途範例
display_name1–64 字，任何語言Dashboard、提示訊息中顯示的名稱Hercules 的 MacBook
description≤ 500 字這台機器的說明14 吋 M4，平常帶著走
roles陣列，小寫英數與連字號這台做哪一類工作；任務可送給 worker@role:<role>["tester","ios-builder"]
labelskey → value，key 小寫英數、底線、連字號，value ≤ 64 字機器屬性；任務以 requires.labels 篩選{"xcode":"16","location":"office"}
powerserver / desktop / laptop決定在線判斷的預設門檻，見 laptop
presence覆寫值（選填）這台機器自己的睡眠 / 離線門檻、睡眠中保留任務的時間、離線是否通知{"asleep_after_sec":120}
owner≤ 64 字負責人hercules
notes≤ 2000 字備註週一到週五在辦公室

角色和標籤怎麼分：角色回答「這台是做什麼的」（例如 builder、tester），任務可以直接送給角色，由第一台有空的機器領取。標籤回答「這台有什麼條件」（例如裝了哪一版 Xcode、在哪個地點），用來在同一個角色裡再篩選。標籤值 * 保留給篩選條件使用，代表「只要有這個 key 就符合」。

生命週期

狀態意義心跳領任務送任務如何進入
pending已用加入碼登錄，等待核准接受（Dashboard 可看到它在線）否否relayctl join（加入碼未設自動核准）
active正常運作接受是是管理者核准，或加入碼設定自動核准
draining不接新任務，跑完手上的；適合要關機維護、帶筆電出門前接受否是relayctl nodes drain <id>
disabled暫停使用（可恢復）接受否否relayctl nodes disable <id>
retired退役，token 全部撤銷，資料保留供查詢拒絕（401）否否relayctl nodes retire <id>

指定送給 draining、disabled 機器的任務會依 的規則提醒發派者；送給角色的任務會自動略過這些機器。

加入一台新機器

  1. 管理者（任何一台有 admin token 的機器，或 Dashboard 的「新增機器」）
    relayctl enroll create --name "Hercules 的 MacBook" --power laptop --role tester --role ios-builder --label xcode=16 --ttl 24h
    畫面顯示一次性加入碼（例如 rle_K7QF-2XMA-PL4D-7RTE）與三個平台各自的加入指令
  2. 新機器
    安裝 Tailscale、Git、Claude Code（並登入）、Node 22、Relay 發行檔（見 ）
  3. 新機器
    relayctl join --hub http://relay-hub:7300 --code rle_K7QF-2XMA-PL4D-7RTE（--node-id 可省略，預設取主機名稱轉小寫）
  4. relayctl join 自動完成
    ① 執行 doctor 檢查（Node、claude、Hub 連線、資料目錄可寫）② 偵測 facts ③ POST /enroll 換得 node token ④ 依平台寫入 node.json、token 檔（並設定權限）、只含 echo 的 profiles.json ⑤ 印出該平台安裝服務的指令
  5. 新機器
    relayctl service install：依平台註冊工作排程器 / launchd / systemd --user，並立刻啟動 Worker
  6. 管理者
    Dashboard「待核准」出現這台機器與它回報的 facts；確認後按「核准」（可順便修改 metadata），狀態轉為 active
  7. 新機器
    依需要編輯 profiles.json 增加 profile；存檔後 Worker 自動重新載入並在下一次心跳回報
  • 加入碼：80 bits 亂數、base32 分組方便手打；只能用一次；預設 24 小時、最長 7 天過期；Hub 只存雜湊；/enroll 每個來源 IP 每分鐘最多 5 次
  • 加入碼可以預先綁定 node_id 與 metadata（preset）；join 指令列給的 --label 等值是「建議」，與 preset 衝突時以 preset 為準
  • 重灌同一台機器：管理者建立綁定原 node_id 的加入碼，新系統 join 後舊 token 自動撤銷，metadata 與歷史保留
  • 改名：改 display_name 即可。真的要換 node_id 時，舊的 retire、新的重新 join

調整 metadata

要做的事relayctl
看一台機器的全部資料relayctl nodes show macbook-hc
加 / 改標籤relayctl nodes set macbook-hc --label location=office --label xcode=16
移除標籤relayctl nodes set macbook-hc --unlabel battery
增減角色relayctl nodes set macbook-hc --add-role tester --remove-role ios-builder
改機器類型與門檻relayctl nodes set macbook-hc --power laptop --asleep-after 120s
看修改歷史 / 還原relayctl nodes history macbook-hc、relayctl nodes rollback macbook-hc --to 3
核准、暫停、退役relayctl nodes approve|drain|disable|enable|retire <id>
  • 修改使用 PATCH /nodes/{id}/meta，必須帶 If-Match: <meta_version>；兩個人同時改時後送出的會收到 409 E_META_CONFLICT，重新讀取後再改，不會互相覆蓋
  • 每一版完整快照存在 node_meta_history，可查誰在何時改了什麼，也可還原（還原本身也是新的一版）
  • 角色與標籤在 Hub 端改完，下一次領任務就用新值；Worker 只用 metadata 顯示與 Log，不影響正在跑的任務

profiles.json 熱重載

  • Worker 監看 profiles.json，存檔後先以 schema 驗證，通過才替換；失敗就保留上一份可用的設定，並在心跳帶 profiles_error，Dashboard 以紅色標示
  • 移除某個 profile 不影響正在用它執行的任務；排隊中指定該 profile 的任務會停在佇列並提醒發派者
