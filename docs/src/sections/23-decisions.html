每項決策寫明「為什麼」，接手的人要推翻時知道原本考量了什麼。

#決策理由放棄的方案
D1中央 Hub（HTTP + SQLite）領任務需要原子操作與租約；需要即時狀態查詢與通知共享資料夾：跨 OS 的 SMB / 同步工具有鎖定與衝突問題，沒有原子領取
D2Worker 用 long-poll 主動拉取Worker 不需開 port、可穿 NAT；延遲在 1 秒內Hub 推送到 Worker：每台都要開入站 port
D3Worker 呼叫 claude -p CLI沿用既有登入；命令列可手動重跑，除錯直觀；三平台參數相同Agent SDK：需另處理驗證，問題不易手動重現
D4MCP 為本機 stdio 程式，不放在 Hub可讀寫本機檔案做附件；token 留在本機設定目錄；可注入 task tokenHub 內建 HTTP MCP：無法存取本機檔案，token 需寫進 Claude 設定
D5SQLite 用 node:sqlite無原生模組，Node 版本變動不需 rebuildbetter-sqlite3：需要 native build，ABI 問題
D6任務只能指定 profile接收端掌握權限邊界，避免跨機注入任務自帶 cwd / allowedTools：等於讓別台決定本機權限
D7預設 max_attempts=1編譯、改檔、推送都有副作用，自動重跑可能造成重複預設重試 3 次
D8Worker 用專屬 clone，不用 git worktree與開發者工作副本隔離；目錄結構單純，不易誤會git worktree
D9Worker 不在任務中等待人回覆避免佔住租約與逾時；以 resume 接續 session任務內 long-poll 等回覆
D10各平台用原生服務管理員（工作排程器 / launchd / systemd）不需第三方套件；重啟、Log、開機啟動都用作業系統內建機制pm2、NSSM 等跨平台包裝程式
D11Hub 放 Linux，用 systemd 強化設定與官方 Node tarball常駐穩定；系統服務不依賴某個使用者的 Volta 安裝Hub 放 Windows 開發機
D12以 Tailscale 作為網路層三平台都有官方用戶端；WireGuard 加密；固定 100.x 位址；手機也能開 Dashboard直接開區網 port + 自管 TLS 憑證
D13Claude 登入模式在每台 node.json 明確設定macOS Keychain 在未登入時不可用；明確設定才不會靠運氣一律沿用互動登入
D14Windows 放 ProgramData，Mac / Linux 放使用者目錄Windows 依團隊規則避免權限問題；Mac / Linux Worker 以使用者執行，不需 sudo；可用 AIPAGER_HOME 統一三平台都放系統目錄
D15os / arch 由 Worker 自動偵測，不可設定避免手動填錯造成任務被送到錯的平台寫在 node.json
D16機器以一次性加入碼動態加入機器會持續增加；加入碼可預設 metadata、可撤銷、預設需核准；join 一次寫好設定，避免手抄 token 出錯預先列清單、手動發 token 並手寫 node.json
D17metadata 放 Hub，profiles 留本機調整名稱、角色、標籤不用登入機器；權限邊界不受 Hub 影響全部放 Hub（Hub 可遠端放寬權限）或全部放本機（每次調整都要登入）
D18在線判斷只看心跳，門檻依機器類型三平台一致，不依賴作業系統的睡眠通知；筆電可以睡很久而不被當成故障使用 OS 睡眠事件 API、單一門檻
D19互動派工預設 confirm，自動流程預設 queue人在場時由人決定等不等；自動流程不中斷，但一定附警告並通知一律排隊（使用者不知道要等多久）、一律拒絕
D20睡眠中保留租約，逾時只算醒著時間筆電闔蓋不該讓任務失敗；三平台的單調時鐘在睡眠期間行為不同，改用偵測到的睡眠區間扣除以牆上時間或系統單調時鐘計算
D21MCP 放 P0（使用者決定）從第一階段就能用自然語言派工、Worker 端回報結構化結果P0 只用 aipagerctl 派工
D22Dashboard 的節點與卡住任務頁放 P0（使用者決定）保留時間依機器而異，需要一眼看出誰睡著、哪些任務因此停住只用 aipagerctl 查詢
D23Worker 預設 login 登入模式使用者為 Claude Max 訂閱；沿用該帳號登入最單純，免登入需求才用 setup-tokenAPI key
D24Worker 略過不認識的 stream-json 類型實測 Claude Code 2.1.317 會輸出設計時未列出的事件類型；版本更新可能再增加遇到未知類型就報錯
