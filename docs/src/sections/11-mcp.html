MCP server 名稱固定為 relay，因此在 Claude Code 中的工具全名為 mcp__relay__<工具名>。工具說明以英文撰寫（模型理解較穩定），內容可為任何語言。三個平台的工具完全相同。metadata 的修改只開放給人（Dashboard、relayctl），MCP 只能讀取。

工具互動任務用途
relay_list_nodes●●列出節點：顯示名稱、在線狀態與沉默多久、機器類型、os / arch、角色、標籤、可用 profile。可依 online、role、label 篩選。派工前先呼叫
relay_describe_node●●單一節點完整資料，含最後出現、最後醒來時間、7 天在線時數
relay_send_task●●派工；可帶 requires_os / requires_arch / requires_labels、on_unavailable、max_wait_sec。wait_seconds（≤ 50）可順便等短任務的結果
relay_wait_task●●最多等 50 秒，回狀態、最近進度、結果；排隊中會附目標目前的在線狀態
relay_get_task●●查單一任務詳情
relay_cancel_task●●取消任務
relay_send_message●●送訊息到某個信箱；對方沒在線時結果附警告
relay_inbox●讀自己的信箱（訊息、任務完成通知、機器醒來通知、審核通知）
relay_ack●標記已讀
relay_attach_file●●上傳 cwd 內的檔案，回 sha256
relay_fetch_attachment●●下載附件到 cwd 內的資料夾
relay_report_progress●回報里程碑（不是每個工具呼叫都報）
relay_submit_result●最後一步呼叫一次，送出結構化結果
relay_permission_prompt●內部使用：由 Worker 以 --permission-prompt-tool 指定，處理權限詢問

派給沒在線的機器時，MCP 怎麼回

互動 session 的 relay_send_task 預設 on_unavailable=confirm。目標沒在線時任務不會建立，工具回傳一段讓 Claude 直接轉告使用者的文字，以及結構化資料：

工具結果的文字部分（模型看到的內容）
⚠ 任務尚未建立：macbook-hc（Hercules 的 MacBook，筆電）已 42 分鐘沒有回應，可能睡著了。
可選擇：
  1. 排隊等它回來（最久等 24 小時）→ 以 on_unavailable="queue" 重新呼叫
  2. 改派給 mac-studio（辦公室 Mac Studio，在線，同樣有 ios profile 與 xcode=16）
  3. 取消
請把以上情況告訴使用者並詢問要怎麼做，不要自行決定。

Worker 任務內部（task 模式）預設 queue：任務照樣建立，結果附警告，發派它的 Claude 會在 summary 中說明「已排隊等待某台機器」。

relay_permission_prompt 的判斷順序

  1. Claude Code 先套用 --allowedTools（直接允許）與 --disallowedTools（直接拒絕）；只有兩者都沒涵蓋的呼叫才會進到這個工具
  2. 比對 profile 的 approval.auto_deny：符合就回 deny，不打擾人
  3. 比對 approval.auto_allow：符合就回 allow
  4. 其餘：建立審核請求（tool_input 截斷到 8 KB，依規則標 risk），以 long-poll 等待，最長 approval.timeout_sec
  5. 回傳格式為一段 JSON 文字：{"behavior":"allow","updatedInput":{…}} 或 {"behavior":"deny","message":"…"}。deny 時 Claude 會收到 message 並自行調整做法
注意：審核等待期間 MCP 工具呼叫會一直掛著，Worker 必須把 MCP_TOOL_TIMEOUT 環境變數設得比審核逾時長（預設 900000 ms = 15 分鐘），否則 Claude Code 會先判定工具逾時。此行為需以實際 CLI 版本驗證，列在 的 T09。
