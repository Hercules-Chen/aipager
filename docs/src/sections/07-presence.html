Worker 每 15 秒向 Hub 發一次心跳。Hub 不去猜機器在做什麼，只看「多久沒有心跳」：超過門檻就當作睡著，再更久就當作離線。門檻依機器類型（power）不同，筆電可以睡很久才算離線。派任務給沒在線的機器時，Hub 會同時提醒發派的那台機器和使用者。

睡眠偵測（Worker 端）

  • Worker 每 5 秒比對一次牆上時間的進度；實際經過的時間比預期多 30 秒以上，就判定剛從睡眠醒來（筆電闔蓋、系統睡眠都會造成這種跳動）
  • 醒來後立刻送心跳並帶 resumed_from_sleep_sec；Hub 記錄 node.presence 事件與 last_wake_at，Dashboard 可以看到每台機器過去 7 天的在線時數
  • 不依賴作業系統的睡眠通知 API，三個平台做法一致

派任務給沒在線的機器

建立任務時，Hub 依目標的在線狀態與發派者選擇的 dispatch.on_unavailable 決定怎麼做：

on_unavailable目標在線目標 asleep / offline / never / draining預設給誰用
confirm建立任務不建立，回 409 E_TARGET_UNAVAILABLE，附目標狀態、其他可用機器、可選動作（排隊 / 改派 / 取消）互動 session 的 MCP 工具、aipagerctl
queue建立任務建立任務並排隊，回應帶 warnings；等目標回來再執行，最久等 max_wait_sec（預設 24 小時）Worker 任務內部派工、流水線 then、直接呼叫 API
reject建立任務不建立，回 409需要立即結果的自動化
  • 目標是角色時：只要有一台符合條件的機器在線就直接建立；全部都沒在線時才套用上表，警告碼為 W_NO_ONLINE_CANDIDATE
  • 其他可用機器（alternatives）：active、online、有同名 profile、符合 requires 的機器，依執行中任務數由少到多排列
  • 警告訊息依 Accept-Language 回 zh-TW 或 en，內容包含顯示名稱、機器類型、沒回應多久，例如：「macbook-hc（Hercules 的 MacBook，筆電）已 42 分鐘沒有回應，可能睡著了。」

執行中睡著

  • 筆電闔蓋時，claude 與 Worker 程序被系統凍結，醒來後會從原地繼續
  • Hub 在 suspend_grace_sec（筆電預設 30 分鐘）內不讓租約過期；醒來後 Worker 續約成功，任務照常完成
  • 超過保留時間：依一般規則處理（可重試就重新排隊，否則 failed，錯誤碼 E_LEASE_LOST，detail 註明 node_asleep）；之後醒來的 Worker 續約會收到 409，立即終止該任務並保留本機結果檔
  • 逾時只計算醒著的時間：Worker 從經過時間扣掉偵測到的睡眠；Hub 端的逾時保護也扣掉該機器 asleep 的區間。三個平台一致
  • macOS 的 caffeinate -i 只能阻止閒置睡眠，闔蓋仍會睡；這正是 suspend grace 要處理的情況
