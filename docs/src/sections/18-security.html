風險對策
Hub 被其他人存取只綁 Tailscale IP；防火牆只允許 100.64.0.0/10；Tailscale ACL 只允許標記為 relay 節點的裝置連 Hub 的 7300；所有 API 需 token。若不用 Tailscale，Hub 前加 Caddy 等 TLS 反向代理
加入碼外洩，陌生機器混入加入碼一次性、預設 24 小時過期、可撤銷；預設需要人工核准，pending 節點不能送或領任務；只有 tailnet 內的裝置連得到 /enroll；每 IP 每分鐘 5 次
metadata 被誤改只有 admin token 可改；每次修改有完整快照與修改者，可一鍵還原；修改不會放寬任何機器的本機權限（profiles 在本機）
Token 外洩Hub 只存雜湊；token 檔依平台限制權限；task token 任務結束 5 分鐘失效；可隨時撤銷
Claude 長效 token 外洩（oauth_token 模式）檔案 600 權限；只注入給 claude 子程序，不出現在 Log、cmdline.txt 或任何封包；外洩時到 Claude 帳號設定撤銷
跨機 prompt injection（A 機被誘導送惡意任務給 B 機）任務只能選 profile；profile 白名單工具；跨機內容包在 <relay_task> 並在 system prompt 聲明為資料；高風險動作走人工審核
任務互相觸發形成迴圈、耗盡用量hop 上限、thread 任務數與花費上限、速率限制、禁止寄給自己
破壞性指令（強推、刪檔、sudo、格式化）profile 的 disallowedTools + auto_deny；工作目錄不乾淨就拒絕執行；Worker 專屬 clone；Worker 永遠不以 root / Administrator 執行
機密外流到其他機器system prompt 禁止讀取與輸出機密；artifacts 只能收集工作目錄內、符合 glob 的檔案；Log 遮罩
Hub 被入侵Hub 不執行任何程式碼、以無 shell 的系統帳號與 systemd 強化設定執行；最壞情況是偽造任務，仍受接收端 profile 限制
