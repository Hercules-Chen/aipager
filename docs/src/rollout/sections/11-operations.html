例行檢查

頻率檢查怎麼看
每天（開始工作時）有沒有睡著的機器、卡住的任務、待審核項目Dashboard 首頁；或 aipagerctl tasks --stuck
每週備份檔存在且有複製到別處Hub 機 ls -l /var/lib/aipager/backup/
每週磁碟與 Log 大小（目前 Log 只按日分檔，尚未依大小輪替，見 B03）Hub du -sh /var/lib/aipager /var/log/aipager；各 Worker 的 logs 與 tasks 目錄
Claude Code 更新後Worker 仍能正常執行對該機送一次 echo 冒煙任務（T03 的指令）

升級 AIPager

先升 Hub，再逐台升 Worker。Hub 重啟時進行中的任務有 120 秒寬限，不會因此失敗。

Hub 機
cd /opt/aipager && sudo git pull && sudo env PATH=/opt/node-v22/bin:$PATH npm ci --omit=dev
sudo systemctl restart aipager-hub
各 Worker（在 repo 目錄 git pull 與 npm ci --omit=dev 之後）
# Windows（系統管理員 PowerShell）
schtasks /End /TN "AIPager Worker"; schtasks /Run /TN "AIPager Worker"
# macOS
launchctl kickstart -k gui/$(id -u)/com.aipager.worker
# Linux
systemctl --user restart aipager-worker

Claude Code 升級

  • 本設計依賴兩個不在 claude --help 清單上的選項（--permission-prompt-tool、--max-turns），新版本有可能改變行為
  • 每次 Claude Code 升級後，先在一台 Linux 或 Mac 執行 npm run test:real-claude（約 0.01 USD），通過後再讓其他 Worker 接正式任務
  • 是否關閉各 Worker 的 Claude Code 自動更新、改為手動升級，見待決定事項 N4

機器異動

情況做法
新增機器enroll create → 新機器 join → service install → Dashboard 核准（同 R2 步驟 2–4）
暫時不用（出差、維修）Dashboard 按「暫停接新任務」（draining），手上的任務會跑完
重灌同一台建立綁定原 node_id 的加入碼後重新 join（T32）
汰換Dashboard 按「退役」，再在該機 aipagerctl service uninstall
改名稱、角色、標籤、保留時間Dashboard 節點頁，或 aipagerctl nodes set；不用碰那台機器

Token 外洩時

  • node token：在 Dashboard 把該機器退役，再以新加入碼重新加入
  • admin token：先用 aipagerctl admin token 建立新的，再以 API DELETE /api/v1/admin/tokens/{token_id} 撤銷舊的（aipagerctl 尚無撤銷指令，見 B09）
