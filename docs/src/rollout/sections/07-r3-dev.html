目標：在你的 Claude Code 對話中直接說「叫 build-pc 編譯」，完成 Q8 的實際流程。需要先回答 Q4（Git server 與存取方式）。

1. 註冊 MCP 與未讀提示

你的電腦：Windows
claude mcp add --scope user --env AIPAGER_AGENT=main aipager -- node "C:\你的repo路徑\bin\aipager-mcp.js" --mode interactive
你的電腦：macOS / Linux
claude mcp add --scope user --env AIPAGER_AGENT=main aipager -- node /你的repo路徑/bin/aipager-mcp.js --mode interactive

未讀提示：把 repo 中 spec/claude/settings.hooks.windows.json（或 .posix.json）的 hooks 內容合併進 ~/.claude/settings.json，並把其中的路徑改成你的 repo 路徑。若原本已有 hooks，把 SessionStart 與 UserPromptSubmit 陣列各自加一項，不要覆蓋原有內容。

2. 互動驗收

  1. 開 Claude Code，輸入 /mcp：aipager 為 connected
  2. 輸入「列出 aipager 的節點」：看到 dev-pc 與 build-pc、在線狀態與 profile
  3. 輸入「叫 build-pc 用 echo profile 執行 hostname，等結果回來告訴我」：Claude 自動派工並回報
  4. 在 build-pc 執行 node bin\aipagerctl.js msg --to main@dev-pc --text "測試訊息 中文 ✓"（不能從你自己的電腦送給自己，Hub 會回 E_SELF_TARGET），回到 Claude 隨便輸入一句：回應前出現 [AIPager] 1 則未讀

3. 第一個實際流程：開發機派編譯給 build-pc（Q8）

  1. 在 build-pc 以 Worker 帳號建立專屬 clone（不要用你平常開發的那份），並確認能 fetch：git clone 你的repo網址 D:\AIPagerWork\專案名。SSH 方式需要為這個 Windows 帳號設定 key（建議唯讀 deploy key）
  2. 在 build-pc 的 profiles.json 加入 build profile：以 repo 中 spec/config/profiles.windows.json 的 build 為範本，改 workdir、repo.allow_remote，以及 allowed_tools 中實際的編譯指令（例如 Bash(dotnet build:*) 或你的 build.ps1）
  3. 在你的電腦 Claude 對話中：「把目前分支推上 Git，叫 build-pc 用 build profile 編譯這個 commit，等結果回來告訴我」
  4. 預期：Claude 先推送、取得 commit，再以 repo={url, ref, commit} 派工；build-pc 在專屬 clone 上 checkout 該 commit 後編譯；結果與錯誤摘要回到對話；Dashboard 任務頁可下載 _stream.jsonl.gz

4. Windows 上的人工審核

在 Claude 對話中要求「叫 build-pc 在工作目錄建立 aipager-test.txt 後執行 git push」。build profile 沒有允許這些動作，Dashboard「等待人工審核」會出現項目，填說明後按拒絕。預期 Claude 收到你的說明原文，沒有推送，並在結果中說明。

出問題時

  • /mcp 顯示 failed：在終端機直接執行 node bin/aipager-mcp.js --mode interactive，若立即結束，看 logs 目錄的 mcp-*.jsonl
  • 任務失敗 E_REPO_NOT_ALLOWED：profile 的 allow_remote 要與 git remote get-url origin 完全相同
  • 任務失敗 E_WORKDIR_DIRTY：專屬 clone 有未提交變更；Worker 不會自動清除，請手動處理
