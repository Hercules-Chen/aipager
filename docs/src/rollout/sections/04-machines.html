本章依「機器」整理工作：每台機器負責哪些步驟、要等誰、做到哪裡必須停下來交給你。各機器上的 Claude 讀 repo 根目錄的 CLAUDE.md 後，會依本章只做自己角色的部分。

角色與機器

代號機器（node_id）作業系統負責的章節做完交出什麼
HHub 機（Tailscale 名稱 aipager-hub，不是 Worker）Ubuntu 24.04 / 26.04 步驟 1–3； 的 T17、T22、T31Hub 在 http://aipager-hub:7300 運作；admin token（只印一次，交給你保存）
D你的電腦（dev-pc，互動機，不跑 Worker）你平常用的電腦 步驟 4； 步驟 0； 步驟 1–2；建立各台的加入碼；送測試任務給 B、M、L 的加入碼；MCP 可在 Claude 對話中派工
Bbuild-pc（Worker，role builder）Windows 步驟 1–4； 步驟 3Worker 開機自動執行；第一個實際編譯流程
Mmacbook-hc（Worker，role tester，筆電）macOS睡眠相關行為的實測結果
Llinux-box（Worker，role tester）Linux跨平台路由的實測結果

先後順序

順序誰做什麼開始前要等
1HR1 步驟 1–3：Tailscale、Node 22、安裝 Hub、admin init、啟動服務R0 完成（main 已有全部內容）
2DR1 步驟 4：存 admin token、手動備份、登入 Dashboard；R2 步驟 0：以 --no-worker 加入成 dev-pcH 完成；你把 admin token 帶到 D
3D → BD 建立 build-pc 的加入碼，你把加入碼帶到 B；B 做 R2 步驟 1–4；你在 Dashboard 核准 build-pc2 完成
4D、BR2 驗收（從 D 送任務給 B）；R3 步驟 1–2 在 D；R3 步驟 3 在 B 建立編譯用 clone3 完成；R3 步驟 3 另需 Git server 與 repo 網址（Q4）
5D → M、D → LD 分別建立加入碼；M 做 R4，L 做 R5（M 與 L 彼此不相依，可先後或同時）4 完成
6H、D、LR6 演練R2 完成後隨時

一次只新接一台（ 的原則一）：前一台的驗收項目都有結果，才開始下一台。

一定要停下來交給你的地方

情況原因各機器的 Claude 該做的事
需要 sudo、Windows 系統管理員權限或輸入密碼只有你能授權列出完整指令並說明用途，由你執行或核准
Tailscale 登入、在管理頁改機器名稱、claude 帳號登入需要瀏覽器與你的帳號告訴你要做什麼，等你回報完成
admin token（apa_）與加入碼（ape_）要從一台機器帶到另一台；token 只印一次印出後請你保存並帶到下一台；不寫進 repo、不寫進任何檔案、不放進 commit 或 PR
Dashboard 核准新機器、審核工具呼叫Q9 決定要人工核准告訴你要核准哪一台，等你回報
闔蓋筆電、重開機、拔網路實體操作說明要做什麼、多久，等你回報再檢查結果
指令結果與文件的「預期」不同可能是程式錯誤或環境差異停止往下做；依 整理回報；不要自行改用其他做法繞過
步驟屬於別的角色避免兩台機器做同一件事或做錯機器不執行，告訴你應該在哪台機器做

取得最新內容

各機器依章節中的位置 clone（Hub 為 /opt/aipager、Windows 為 C:\Program Files\AIPager、Mac 為 /opt/aipager、Linux Worker 為 ~/aipager）。之後更新一律 git pull 後 npm ci --omit=dev，再重啟服務（ 的「升級 AIPager」）。Windows 的安裝位置在 Program Files，git pull 要在系統管理員 PowerShell 執行。
