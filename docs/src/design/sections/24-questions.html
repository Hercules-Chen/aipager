#問題決定
Q1機器清單不預先列出；改為動態加入、metadata 可隨時調整（）
Q2網路使用 Tailscale
Q3Hub 作業系統Ubuntu 24.04 LTS / 26.04 LTS
Q4Worker 存取 Git server 的方式SSH，並為 Worker 帳號設定唯讀 deploy key。Git server 的種類與 repo 網址屬於環境資訊，在上線計畫 R3 開始前提供
Q5Claude 登入方式Claude Max 訂閱。Worker 預設 claude_auth.mode = "login"；需要免登入的機器（例如 Mac LaunchDaemon）才用 claude setup-token 的 oauth_token；不使用 API key
Q6Mac 是否會睡眠一開始是筆電；以心跳判斷，派工時提醒（）
Q7審核與失敗通知不主動推播，只用 Hub 查詢：Dashboard（瀏覽器，含手機）、aipagerctl、MCP 工具，以及 Claude 對話中的未讀與待審核提示。部署時 webhooks 設為 []；webhook 功能保留，之後需要推播時再啟用（D29）
Q8第一個實際流程開發機派編譯給 Windows build-pc；P0 以此為驗收情境
Q9新機器加入是否需核准需要人工核准；P0 就提供 aipagerctl nodes approve 與 Dashboard 核准按鈕
Q10睡眠保留時間依機器不同：用每台 metadata 的 presence.suspend_grace_sec 覆寫預設；Dashboard 首頁要能看到誰睡著、睡多久、哪些任務因此卡住（P0）
Q11MCP 放哪個階段放 P0，與 Hub、Worker 一起完成
